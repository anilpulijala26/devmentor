## What You Will Learn

- Coordinate client and server validation checks.
- Display field-level validation error messages.
- Handle interface loading and submission states.

---

## Why This Matters in Real Projects

Uncoordinated validations result in users submitting forms only to receive server errors. Syncing validations ensures immediate feedback in the UI while enforcing the same validation rules on the backend.

<SeniorNote>
Use the same validation library (like Zod) on both the client and the server. This allows you to share schema rules, reducing code duplication.
</SeniorNote>

---

## Concept Explanation

### Validation Synchronization

- **Client Validation**: Validates user inputs instantly on typing or blur, providing fast feedback.
- **Server Validation**: Enforces the same validation rules on backend API routes, protecting database schemas.
- **Shared Schemas**: Using Zod allows you to import the same validation rules in both frontend and backend codebases.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Shared Zod schema for client and server validation
import { z } from 'zod';

export const userRegistrationSchema = z.object({
  username: z.string().min(3, 'Username must be at least 3 characters.'),
  email: z.string().email('Invalid email format.'),
  password: z.string().min(8, 'Password must be at least 8 characters.')
});
```

## Common Mistakes

Here is an example of incorrect setups vs clean, optimized configurations.

<CommonMistake
  title={"Validating inputs only on the client side"}
  badDesc={"Enforcing validation rules only in frontend forms. Attackers can bypass client validation by sending raw API requests directly to backend routes."}
  badCode={"// Server-side saves inputs without checks\napp.post('/register', (req, res) => {\n  db.save(req.body); // Vulnerable: missing backend validation!\n});"}
  goodDesc={"Always enforcing validation rules on the backend, even if client validation is active."}
  goodCode={"// Server-side validates inputs against the same schema\napp.post('/register', validate(userRegistrationSchema), controller);"}
/>

## Interview Tip

<InterviewTip question={"Why should you validate on both the client and the server?"}>
Client-side validation provides fast feedback, improving the user experience. Server-side validation is required for security, as frontend code can be modified or bypassed by sending requests directly to the API.
</InterviewTip>
