## What You Will Learn

- Configure project workspaces using NPM/Yarn workspaces.
- Share schema models and types across packages.

---

## Why This Matters in Real Projects

Managing frontend and backend applications in separate repositories makes sharing types, schemas, and configurations difficult. Organizing projects into a monorepo workspace simplifies dependency management and allows code sharing.

<SeniorNote>
Store shared schemas (like Zod schemas) and TypeScript interfaces in a shared workspace package. Frontend and backend packages can then import these shared models directly.
</SeniorNote>

---

## Concept Explanation

### Workspace Monorepos

- **Monorepo**: A single repository containing multiple projects or packages.
- **Workspaces**: Package manager configurations (like NPM or Yarn workspaces) that link local packages, allowing them to be imported like external dependencies.
- **Shared Packages**: Specialized packages containing shared logic (like schemas or types) imported by both frontend and backend applications.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Root package.json workspaces configuration
{
  "name": "codenivra-workspace",
  "private": true,
  "workspaces": [
    "apps/web",      // Next.js Frontend
    "apps/api",      // Express Backend
    "packages/shared" // Shared schemas, validations and types
  ],
  "scripts": {
    "dev": "npm run dev --workspaces",
    "build": "npm run build --workspaces"
  }
}
```

## Common Mistakes

Here is an example of incorrect setups vs clean, optimized configurations.

<CommonMistake
  title={"Duplicate Schema Definitions in Frontend and Backend Projects"}
  badDesc={"Maintaining separate copies of validation schemas in both frontend and backend codebases, leading to validation mismatches."}
  badCode={"// apps/web/validation.js (Manual copy of schema rules)\n// apps/api/validation.js (Duplicate copy of schema rules)"}
  goodDesc={"Storing validation schemas in a shared package and importing them across workspaces."}
  goodCode={"// packages/shared/schemas.js (Single source of truth)\nimport { registrationSchema } from '@codenivra/shared'; // Imported in both apps"}
/>

## Interview Tip

<InterviewTip question={"What are the benefits of using monorepos?"}>
Monorepos simplify code sharing (like sharing types and schemas), coordinate dependency versions, and allow atomic changes across frontend and backend codebases in a single commit.
</InterviewTip>
