# Docker Basics

Docker packages your app, runtime, and dependencies into a reproducible image. This prevents “works on my machine” bugs and makes deployments consistent.

## Watch: Docker Basics

<YouTubeEmbed videoId="dQw4w9WgXcQ" />

## Key Concepts

- **Image**: a packaged snapshot of your app and runtime
- **Container**: a running instance of an image
- **Dockerfile**: instructions to build an image
- **Registry**: storage for images (e.g., Docker Hub)

<SeniorNote>
If your app behaves differently in staging than on your laptop, Docker is often the fix.
</SeniorNote>

## Minimal Dockerfile (Next.js)

```dockerfile
# Dockerfile
FROM node:20-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

FROM node:20-alpine AS builder
WORKDIR /app
COPY . .
COPY --from=deps /app/node_modules ./node_modules
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/package.json ./package.json
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["npm", "run", "start"]
```

## Running with .env

```bash
docker build -t codenivra .
docker run --env-file .env.local -p 3000:3000 codenivra
```

<Pitfall>
Never bake secrets into your image. Inject them at runtime using `.env` or your cloud provider’s secret manager.
</Pitfall>

## docker-compose (App + Database)

```yaml
version: "3.9"
services:
  app:
    build: .
    ports:
      - "3000:3000"
    env_file:
      - .env.local
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app_password
      POSTGRES_DB: app_db
    ports:
      - "5432:5432"
```
