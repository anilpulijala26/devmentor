## Why This Matters in Real Projects

Ad-hoc, un-reviewed changes pushed directly to main branches are a common cause of production outages. Enforcing code reviews and PR checks ensures quality standards before code is merged.

<SeniorNote>
Configure branch protection rules to block merges unless code reviews are approved and automated CI pipelines pass successfully.
</SeniorNote>

---

## Concept Explanation

### Collaborative Git Workflows

- **GitHub Flow**: Simple workflow where developers create feature branches off main, submit PRs, run checks, and merge back to main.
- **Branch Protection**: Repository settings that restrict direct pushes to main branches, requiring code reviews and status checks.
- **PR Templates**: Markdown templates that guide developers to write detailed descriptions of changes and testing steps.

## Interview Tip

<InterviewTip question={"What is the difference between Git merge and git rebase?"}>
git merge combines histories by creating a new merge commit, preserving source branch histories. git rebase reapplies commits on top of another base, creating a linear history without merge commits.
</InterviewTip>
