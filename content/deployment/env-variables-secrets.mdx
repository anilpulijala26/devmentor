## What You Will Learn

- Understand the difference between development and production configurations.
- Store API keys and database credentials securely.
- Configure environment variables in cloud hosting environments.

---

## Why This Matters in Real Projects

Exposing production keys in code repositories is a major security risk. Managing environment variables securely prevents credentials leaks, protecting staging and production systems.

<SeniorNote>
Never store credentials in code files. In production, load environment variables using hosting panels (like Vercel or AWS ECS) or secure key vaults.
</SeniorNote>

---

## Concept Explanation

### Secret Management Practices

- **Dotenv Files**: Local configuration files (`.env`) containing key-value configurations. Should be added to `.gitignore`.
- **Environment Scopes**: Isolate staging and production credentials.
- **Secrets Managers**: Specialized cloud services (like AWS Secrets Manager) that encrypt, store, and rotate API keys securely.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Safe configuration module verifying keys
import dotenv from 'dotenv';
dotenv.config();

const requiredKeys = ['DATABASE_URL', 'JWT_SECRET'];

for (const key of requiredKeys) {
  if (!process.env[key]) {
    throw new Error(`CRITICAL SETUP FAILURE: Environment key ${key} is missing.`);
  }
}

export const config = {
  dbUrl: process.env.DATABASE_URL,
  jwtSecret: process.env.JWT_SECRET,
  port: process.env.PORT || 5000
};
```

## Interview Tip

<InterviewTip question={"Why should you never store credentials in code repositories?"}>
Committing credentials exposes them to anyone with repository access. Attackers use automated tools to scan repositories for keys, exposing databases and server systems.
</InterviewTip>
