## What You Will Learn

- Manage AWS security permissions using IAM policies.
- Configure private S3 buckets for asset storage.
- Distribute static assets globally using CloudFront CDN.

---

## Why This Matters in Real Projects

Exposing access keys or leaving storage buckets public is a major security risk. Using IAM policies to restrict access and serving assets through CDNs secures storage and improves load times globally.

<SeniorNote>
Always keep S3 buckets private. Restrict access to bucket resources, and serve assets to users using CloudFront CDN with Origin Access Identity (OAI) policies.
</SeniorNote>

---

## Concept Explanation

### IAM, S3 & CDN Architectures

- **IAM (Identity and Access Management)**: Controls resource access permissions using policies.
- **S3 Bucket**: Scalable cloud storage containers.
- **CloudFront CDN**: Global content delivery network that caches assets at edge locations to reduce latency.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// AWS S3 bucket configuration policy example
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontOAI",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::cloudfront:user/CloudFront-Origin-Access-Identity-OAI"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::codenivra-assets/*"
    }
  ]
}
```

## Interview Tip

<InterviewTip question={"What is an Origin Access Control (OAC) in AWS?"}>
OAC is an AWS security configuration that restricts S3 bucket access to CloudFront CDN instances only, preventing users from bypassing CDNs to access bucket resources directly.
</InterviewTip>
