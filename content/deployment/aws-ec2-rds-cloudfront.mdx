## Why This Matters in Real Projects

Managing databases and server scaling manually is difficult. Using managed cloud services (RDS, Lambda) automate backups, scaling, and domain routing.

<SeniorNote>
Place RDS databases inside private subnets without public IP addresses. Allow access to database ports only from application server security groups.
</SeniorNote>

---

## Concept Explanation

### Cloud Database & DNS Architectures

- **AWS RDS**: Managed relational database service that automates patching, backups, and scaling.
- **Route 53**: Scalable cloud DNS web service that routes user requests to cloud resources.
- **AWS Lambda**: Serverless compute service that runs code on demand in response to events.

## Interview Tip

<InterviewTip question={"Why should database instances be placed in private subnets?"}>
Private subnets lack public IP addresses, preventing direct internet access. Placing databases in private subnets blocks external network attacks, allowing queries only from application servers.
</InterviewTip>
