## Why This Matters in Real Projects

PaaS providers can be expensive at scale. Deploying servers to cloud virtual instances (like AWS EC2) or App Services provides more control over resources and reduces hosting costs at scale.

<SeniorNote>
Restrict security group ingress access. Do not expose database ports (e.g. 5432) to wildcard IP addresses '0.0.0.0/0'. Whitelist only trusted application server IPs.
</SeniorNote>

---

## Concept Explanation

### Cloud VM & App Service Hosting

- **AWS EC2**: Cloud virtual instances that provide full OS controls over server instances.
- **Security Groups**: Virtual firewalls that control traffic routing permissions (e.g. whitelisting ports 80 and 443).
- **Azure App Service**: Managed PaaS hosting for web applications, managing scaling and OS updates automatically.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// AWS EC2 instance launch script using AWS CLI
# Launch an EC2 instance using Amazon Linux AMI
aws ec2 run-instances \
  --image-id ami-0c55b159cbfafe1f0 \
  --count 1 \
  --instance-type t2.micro \
  --key-name DevPrivateKey \
  --security-group-ids sg-123456 \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=CodeNivraAPI}]'
```

## Common Mistakes

Here is an example of incorrect setups vs clean, optimized configurations.

<CommonMistake
  title={"Exposing SSH Port 22 to Wildcard IPs"}
  badDesc={"Setting security group ingress parameters to allow SSH access on port 22 from '0.0.0.0/0', exposing servers to brute-force attacks."}
  badCode={"// Ingress rule: Port 22 -> Source: 0.0.0.0/0 (VULNERABILITY)"}

## Interview Tip

<InterviewTip question={"What is the difference between AWS EC2 and AWS Lambda?"}>
AWS EC2 is a virtual server instance that runs continuously, giving you full OS control and charging per hour. AWS Lambda is a serverless function that runs code only in response to events, charging per execution.
</InterviewTip>
