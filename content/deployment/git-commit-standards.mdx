## Why This Matters in Real Projects

Inconsistent commit messages make analyzing project histories difficult. Enforcing Conventional Commits standards and running pre-commit hooks prevents malformed commits, keeping histories clean.

<SeniorNote>
Use Husky to configure git hooks that run linters and test suites before code commits are allowed. This blocks syntax errors early.
</SeniorNote>

---

## Concept Explanation

### Conventional Commits & Hooks

- **Conventional Commits**: Format standard for commit messages (e.g. `feat: add auth`, `fix: resolve memory leak`).
- **Husky**: Library that manages git hooks, running scripts on events like commits or pushes.
- **Lint-Staged**: Runs linters only on files modified in current commits, speeding up hook checks.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// package.json pre-commit hook configuration example
{
  "name": "production-app",
  "devDependencies": {
    "husky": "^9.0.0",
    "lint-staged": "^15.0.0"
  },
  "husky": {
    "hooks": {
      "pre-commit": "lint-staged"
    }
  },
  "lint-staged": {
    "*.js": [
      "eslint --fix",
      "prettier --write"
    ]
  }
}
```

## Interview Tip

<InterviewTip question={"What is a Git Hook?"}>
A Git Hook is a script that runs automatically on specific Git lifecycle events (like pre-commit, post-merge, or pre-push), allowing you to automate validations and checks.
</InterviewTip>
