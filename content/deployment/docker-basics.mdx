## Why This Matters in Real Projects

Default single-stage Docker configurations create massive images containing build tools, increasing deployment times. Multi-stage builds compile slim, production-only containers, reducing image sizes and security footprints.

<SeniorNote>
Always add a non-root user configuration to Dockerfiles. Running container processes as root exposes hosts to security vulnerabilities if containers are compromised.
</SeniorNote>

---

## Concept Explanation

### Docker Containers & Layers

- **Docker Image**: Pre-configured templates containing code, runtime layers, and tools.
- **Image Layering**: Every instruction in a Dockerfile creates an image layer. Reordering steps optimizes build caching.
- **Multi-Stage Build**: Uses temporary build stages to compile assets, copying only production dependencies into final images to keep sizes small.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Production Multi-Stage Dockerfile example
# Stage 1: Compile dependencies and build assets
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Create production runner container
FROM node:20-alpine AS runner
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY --from=builder /app/dist ./dist

# De-escalate root credentials
USER node
EXPOSE 5000
CMD ["node", "dist/app.js"]
```

## Common Mistakes

Here is an example of incorrect setups vs clean, optimized configurations.

<CommonMistake
  title={"Running Containers as Root"}
  badDesc={"Omitting non-root user configurations in Dockerfiles. If containers are compromised, attackers gain root permissions on the host system."}
  badCode={"FROM node:20-alpine\nWORKDIR /app\nCOPY . .\n# Runs process as root by default!\nCMD [\"node\", \"app.js\"]"}
  goodDesc={"Always de-escalating privileges to non-root users inside runner stages."}

## Interview Tip

<InterviewTip question={"What is a multi-stage Docker build?"}>
A multi-stage Docker build uses temporary builder stages to install dependencies and compile code. It then copies only compiled production assets into a final, clean runner stage, keeping container image sizes small by omitting build tools.
</InterviewTip>
