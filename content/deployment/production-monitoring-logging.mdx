## Why This Matters in Real Projects

Relying on users to report crashes is not scalable. Automating performance monitoring and alert channels notifies teams instantly when server errors occur, speeding up bug fixes.

<SeniorNote>
Configure uptime checks to ping health check endpoints (/healthz) every minute. If endpoints fail, configure alert channels to notify teams immediately.
</SeniorNote>

## Concept Explanation

### Application Telemetry & Logging

- **Error Monitoring**: Capture error stack traces and environment states in real time (e.g. Sentry).
- **APM (Application Performance Monitoring)**: Tracks processing times, request volumes, and query latency (e.g. Datadog).
- **Uptime Checks**: Automated HTTP ping checks that verify servers are active and responding.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Integrating Sentry error monitoring in Express
import express from 'express';
import * as Sentry from '@sentry/node';

const app = express();

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  environment: process.env.NODE_ENV
});

// Request handlers must be the first middleware
app.use(Sentry.Handlers.requestHandler());

app.get('/', (req, res) => {
  res.send('Hello World');
});

// Error handlers must be registered before other error middlewares
app.use(Sentry.Handlers.errorHandler());

app.use((err, req, res, next) => {
  res.status(500).json({ error: 'Internal Server Error' });
});
```

## Interview Tip

<InterviewTip question={"What is the difference between logging and metrics?"}>
Logging records specific events in detail (like stack traces on error runs). Metrics record numeric telemetry aggregates over time (like request counts, memory usage, or query latency).
</InterviewTip>
