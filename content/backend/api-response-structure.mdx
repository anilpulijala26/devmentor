## Why This Matters in Real Projects

Inconsistent API structures require custom parsers for each endpoint, increasing frontend bugs. Having standard response formats and path versioning routes ensures predictable, backward-compatible API designs.

<SeniorNote>
Always wrap response data in an envelope object (e.g. `data: {"{"{"}"}{"}"}`). This allows you to add metadata parameters (like pagination counters or audit tags) later without breaking client integrations.
</SeniorNote>

## Concept Explanation

### API Response Formats

A standardized REST response uses consistent wrapper envelopes:
- **Success Envelopes**: Contains the requested data alongside potential metadata:
  `{ "data": [...], "meta": { "total": 100 } }`
- **Error Envelopes**: Contains structured details about failures, listing paths and parameters:
  `{ "error": { "message": "Failed validation", "details": [...] } }`

### Versioning Strategies
Versioning isolates breaking API changes. The industry standard is URL path versioning:
`https://api.codenivra.com/v1/users`

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Standardizing JSON formats and version routes
import express from 'express';
const app = express();
const v1Router = express.Router();

// Custom success response envelope utility
const sendSuccess = (res, data, status = 200, meta = {}) => {
  res.status(status).json({ data, meta });
};

// Custom error response envelope utility
const sendError = (res, message, status = 400, details = []) => {
  res.status(status).json({
    error: { message, status, details }
  });
};

v1Router.get('/users', (req, res) => {
  const users = [{ id: 1, name: 'Alice' }];
  sendSuccess(res, users, 200, { count: users.length });
});

app.use('/api/v1', v1Router);
```

## Interview Tip

<InterviewTip question={"Why is path-based versioning (/v1) preferred over header versioning?"}>
Path versioning is visible, easy to test in web browsers, and works naturally with caching proxies. Header versioning is clean, but makes it harder to share links, verify logs, or test routes via curl.
</InterviewTip>
