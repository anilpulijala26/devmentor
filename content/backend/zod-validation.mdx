## Why This Matters in Real Projects

Unvalidated user input is a major cause of database errors and security vulnerabilities. Validating request bodies and parameters using Zod schemas blocks malformed inputs before they reach business service layers.

<SeniorNote>
Use Zod's `.strict()` parser option to reject requests containing unexpected parameters. This prevents malicious payload injections.
</SeniorNote>

---

## Concept Explanation

### Input Schema Validations

Zod is a TypeScript-first schema declaration and validation library:
- **Declarative Schema**: Define validation structures (e.g. string lengths, email formats).
- **Type Inference**: Extract TypeScript types directly from schemas.
- **Middleware Validation**: Intercept requests, validate payloads against schemas, and automatically return 400 status codes containing error logs if validation fails.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Express middleware utilizing Zod schema validations
import express from 'express';
import { z } from 'zod';
const app = express();
app.use(express.json());

// 1. Declare payload validation schema
const registrationSchema = z.object({
  email: z.string().email('Invalid email address format.'),
  password: z.string().min(8, 'Password must be at least 8 characters long.'),
  age: z.number().min(18, 'Users must be 18 years or older.')
}).strict();

// 2. Validate request middleware
const validateRequest = (schema) => (req, res, next) => {
  const result = schema.safeParse(req.body);
  if (!result.success) {
    return res.status(400).json({
      error: {
        message: 'Validation failed.',
        details: result.error.errors.map(err => ({
          field: err.path.join('.'),
          message: err.message
        }))
      }
    });
  }
  req.body = result.data; // Save validated data
  next();
};

app.post('/register', validateRequest(registrationSchema), (req, res) => {
  res.status(201).json({ success: true });
});
```

## Interview Tip

<InterviewTip question={"What is the difference between parse() and safeParse() in Zod?"}>
parse() throws a ZodError exception if validation fails, requiring try-catch blocks. safeParse() does not throw exceptions; it returns an object containing success flags: `{ success: true, data: T }` or `{ success: false, error: ZodError }`.
</InterviewTip>
