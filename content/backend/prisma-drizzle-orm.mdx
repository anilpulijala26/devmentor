## Why This Matters in Real Projects

Writing raw SQL strings inside code repositories can lead to SQL injection vulnerabilities and is difficult to maintain. Using ORMs like Prisma or Drizzle provides type-safe database queries and automated schema migrations.

<SeniorNote>
Always configure database connection pooling on application boot. If connection pools are misconfigured, application instances can exhaust database connection limits during traffic spikes.
</SeniorNote>

## Concept Explanation

### ORM Schemas and Migrations

- **Schema Definition**: Model tables and relationships in a single configuration file (e.g. `schema.prisma` or Drizzle schemas).
- **Type-Safety**: ORMs generate TypeScript interfaces matching schema definitions, preventing property query errors.
- **Migrations**: Automated migrations track changes to database schemas over time, allowing schemas to be updated across environments.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// prisma/schema.prisma schema definition example
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  posts     Post[]
  createdAt DateTime @default(now())
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  authorId Int
  author   User   @relation(fields: [authorId], references: [id])
}
```

## Interview Tip

<InterviewTip question={"What is the difference between Prisma and Drizzle?"}>
Prisma uses a custom schema language and runs a query engine binary to generate queries, offering rich features. Drizzle uses standard TypeScript schemas and returns raw SQL queries directly, offering faster performance and a smaller footprint.
</InterviewTip>
