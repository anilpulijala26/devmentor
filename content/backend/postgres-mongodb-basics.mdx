## Why This Matters in Real Projects

Choosing the incorrect database engine early in development is a costly mistake. PostgreSQL provides strict validation schemas and relationships, while MongoDB offers flexible document structures for rapidly changing datasets.

<SeniorNote>
Do not choose MongoDB simply because it uses JSON objects. If your data features complex relationships (like users, orders, and products), use PostgreSQL to enforce relationships and data consistency.
</SeniorNote>

## Concept Explanation

### SQL vs NoSQL Tradeoffs

- **PostgreSQL (SQL)**:
  - Relational database utilizing strict tabular schemas.
  - Supports ACID transactions (Atomicity, Consistency, Isolation, Durability).
  - Best for complex data relationships and transactional integrity.
- **MongoDB (NoSQL)**:
  - Document-based database utilizing dynamic BSON schemas.
  - Prioritizes write performance and horizontal scaling (sharding).
  - Best for flexible document structures and rapid scaling.

## Interview Tip

<InterviewTip question={"What is the CAP Theorem?"}>
The CAP Theorem states that a distributed data store can guarantee at most two of three properties: Consistency (all nodes see the same data at the same time), Availability (every request receives a response), and Partition Tolerance (the system continues to operate despite network partition drops).
</InterviewTip>
