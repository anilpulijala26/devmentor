## Why This Matters in Real Projects

Incorrect permission checks are a common cause of data exposure (Broken Object Level Authorization). Constructing modular, type-safe authorization middlewares ensures that users can only access endpoints matching their assigned role permissions.

<SeniorNote>
Design authorization checks using granular permissions (e.g. `write:posts`) instead of generic roles (e.g. `editor`). This allows you to update role permissions later without modifying route middleware code.
</SeniorNote>

---

## Concept Explanation

### RBAC vs PBAC

- **Role-Based Access Control (RBAC)**: Groups permissions into user roles (e.g., admin, editor, subscriber) and assigns roles to users.
- **Permission-Based Access Control (PBAC)**: Checks for specific permissions (e.g., `edit:users`) rather than user roles, providing more granular access control.
- **Authorization Middleware**: Intercepts requests, decodes user credentials, checks role permissions, and returns a 403 Forbidden status if validation fails.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Modular RBAC permissions middleware in Express
import express from 'express';
const app = express();

// Mock user profiles data object
const userPermissions = {
  admin: ['read:users', 'write:users', 'delete:users'],
  editor: ['read:users', 'write:users'],
  user: ['read:users']
};

// Authorization Middleware
const requirePermission = (permission) => (req, res, next) => {
  const user = req.user; // Set by authentication middleware
  if (!user || !user.role) {
    return res.status(401).json({ error: 'Unauthenticated.' });
  }
  
  const permissions = userPermissions[user.role] || [];
  if (!permissions.includes(permission)) {
    return res.status(403).json({ error: 'Forbidden: Insufficient privileges.' });
  }
  
  next();
};

app.delete('/api/users/:id', requirePermission('delete:users'), (req, res) => {
  res.json({ message: 'User deleted.' });
});
```

## Interview Tip

<InterviewTip question={"What is the difference between Authentication and Authorization?"}>
Authentication (AuthN) verifies the identity of a user (e.g., checking usernames and passwords during login). Authorization (AuthZ) verifies the permissions of an authenticated user (e.g., checking if a user has permission to delete a resource).
</InterviewTip>
