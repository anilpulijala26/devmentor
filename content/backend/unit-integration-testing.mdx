## Why This Matters in Real Projects

Deploying code without automated tests is a major risk. Unit tests verify isolated business functions quickly, while integration tests check database queries and routing modules.

<SeniorNote>
Write independent unit tests that do not share states. Use lifecycle hooks (`beforeEach`, `afterEach`) to clean up test fixtures between runs.
</SeniorNote>

---

## Concept Explanation

### Automated Testing Categories

- **Unit Testing**: Tests individual functions or modules in isolation. Dependencies (like database clients) are mocked out for speed.
- **Integration Testing**: Tests how multiple modules interact, verifying database queries and API route integrations.
- **Test Runners**: Libraries (like Jest or Vitest) that execute tests, assert outcomes, and collect code coverage reports.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Unit testing utility functions with Jest
// math.js
export const applyDiscount = (price, discountPercent) => {
  if (discountPercent < 0 || discountPercent > 100) {
    throw new Error('Invalid discount percentage.');
  }
  return price - (price * (discountPercent / 100));
};

// math.test.js
import { applyDiscount } from './math';

describe('applyDiscount unit tests', () => {
  it('correctly calculates discount values', () => {
    expect(applyDiscount(100, 20)).toBe(80);
  });
  
  it('throws an error on invalid percentage thresholds', () => {
    expect(() => applyDiscount(100, -5)).toThrow('Invalid discount percentage.');
  });
});
```

## Common Mistakes

Here is an example of incorrect setups vs clean, optimized configurations.

<CommonMistake
  title={"Shared state between test suites"}
  badDesc={"Modifying global variables or database records in one test without cleanup, causing subsequent tests to fail unpredictably."}
  badCode={"let user;\nit('creates user', () => {\n  user = { id: 1 }; // Sets shared state\n});\nit('reads user', () => {\n  expect(user.id).toBe(1); // Fails if executed out of order!\n});"}
  goodDesc={"Using lifecycle hooks to reset configurations between test runs."}
  goodCode={"beforeEach(() => {\n  user = null; // Clean state before each test run\n});"}
/>
