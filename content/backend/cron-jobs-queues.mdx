## Why This Matters in Real Projects

Processing heavy tasks (like sending newsletters or compiling reports) inside HTTP request cycles blocks users. Offloading these tasks to background workers improves server response times.

<SeniorNote>
Always verify incoming webhook signatures. If signatures are not validated, malicious actors can send fake webhook events to trigger unauthorized actions.
</SeniorNote>

---

## Concept Explanation

### Background Task Workers & Webhooks

- **Message Queues**: Decouple task generation from task execution. Job parameters are stored in queues (like Redis) for workers to process.
- **Cron Jobs**: Run automated tasks at scheduled times (e.g. daily database cleanups).
- **Webhooks**: Real-time notifications sent by external APIs (like Stripe) when events occur, requiring signature verification.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// BullMQ job scheduler implementation
import { Queue, Worker } from 'bullmq';
import IORedis from 'ioredis';

const connection = new IORedis(process.env.REDIS_URL);

// 1. Configure the task Queue
const emailQueue = new Queue('emailSender', { connection });

export async function queueEmailTask(userId, template) {
  await emailQueue.add('sendEmail', { userId, template }, {
    attempts: 3,
    backoff: 1000 // Retry with 1s delay on failures
  });
}

// 2. Configure the background Worker process
const emailWorker = new Worker('emailSender', async (job) => {
  console.log(`Processing email job ${job.id} for user ${job.data.userId}...`);
  // Process email delivery...
}, { connection });
```

## Interview Tip

<InterviewTip question={"Why is Redis used by libraries like BullMQ to manage queues?"}>
Redis is used because it runs in memory, providing high write speeds. It also supports atomic operations (via Lua scripts) that allow jobs to be locked and distributed across multiple worker processes without race conditions.
</InterviewTip>
