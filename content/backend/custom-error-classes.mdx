## What You Will Learn

- Build custom Error classes inheriting from base Exception layers.
- Eliminate try-catch boilerplates using higher-order handlers.
- Assign custom status codes to specific error classes.

---

## Why This Matters in Real Projects

Writing repetitive try-catch blocks inside route handlers clutters codebases. Custom error classes classify failures with specific status codes, and higher-order functions wrap handlers to clean up code.

<SeniorNote>
Always set `this.name = this.constructor.name` and capture stack traces using `Error.captureStackTrace(this, this.constructor)` inside custom Error class constructors to ensure accurate diagnostic details.
</SeniorNote>

---

## Concept Explanation

### Custom Error Classes

By extending JavaScript's built-in `Error` class, we can bind HTTP metadata parameters directly to custom error objects:
- **Class Classification**: Create specialized error classes (like `NotFoundError`, `BadRequestError`, `UnauthorizedError`).
- **Dynamic Status**: Assign default status codes to each class.
- **Async Catcher Wrappers**: Use higher-order functions to wrap async route handlers, catching rejections and passing them to `next()` automatically.

## Code Example

Below is a configuration file matching senior standards:

```javascript
// Custom error class and async wrapper implementation
// 1. Create Base API Error class
class APIError extends Error {
  constructor(message, status = 500) {
    super(message);
    this.status = status;
    this.name = this.constructor.name;
    Error.captureStackTrace(this, this.constructor);
  }
}

class NotFoundError extends APIError {
  constructor(message = 'Resource not found.') {
    super(message, 404);
  }
}

// 2. Async Handler Catcher Wrapper
const catchAsync = (fn) => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
};

// 3. Usage in route handler (No try-catch blocks!)
app.get('/users/:id', catchAsync(async (req, res) => {
  const user = await db.find(req.params.id);
  if (!user) {
    throw new NotFoundError('User record not found.'); // Caught and forwarded automatically
  }
  res.json(user);
}));
```

## Common Mistakes

Here is an example of incorrect setups vs clean, optimized configurations.

<CommonMistake
  title={"Using Generic Errors for Everything"}
  badDesc={"Throwing generic Error objects with messages like 'User not found' and manually setting status codes inside handlers."}
  badCode={"app.get('/user', async (req, res, next) => {\n  if (!user) {\n    const err = new Error('User not found');\n    err.statusCode = 404; // Repetitive and error-prone!\n    return next(err);\n  }\n});"}
  goodDesc={"Throwing semantic custom errors directly."}

## Interview Tip

<InterviewTip question={"What is the purpose of Error.captureStackTrace in Node.js?"}>
Error.captureStackTrace creates a '.stack' property on target objects. By passing the constructor name as the second parameter, it excludes constructor logic frames from stack traces, keeping log diagnostics clean.
</InterviewTip>
